# 待办：钉钉卡片快捷提问（P1，阻塞于钉钉权限）

**状态**：待办 / 阻塞（暂时无法获取钉钉卡片平台权限与回调权限）  
**来源**：钉钉帮助首屏反馈第 6 条「钉钉能力没用上：没有卡片按钮、没有『点一下就提问』，全靠复制整句」  
**已完成的 P0**：问候只回一句、帮助/文档分层、隐藏编号、示例换成业务问法（提交 `395b3ae`）。

## 目标体验

单聊里发「你好」或「帮助」时，除短帮助文本外，展示一张卡片：

- 标题：企业知识库助手
- 正文：同 P0 短帮助（能查条款/条件/责任人/时限）
- 按钮（示例，最终以 `config/discovery_questions.json` 的种子为准）：
  1. 跑水事件环境部先做什么
  2. 有限空间作业票谁审批
  3. 日常小修多久完成
  4. 查看可查文档
- 点击按钮 = 直接把对应问题发给机器人，进入现有 QA（权限、限流、审计、引用全部复用）。
- 群聊保持不回复，不投放卡片。

## 技术方案（待权限到位后实施）

1. **钉钉卡片模板**：在开发者后台「卡片平台」创建 AI 卡片模板（markdown 变量 + 按钮），拿到 `ai_template_id`，填入 `dingtalk.card.ai_template_id`；需要时打开 `streaming_enabled`。
2. **创建卡片**：`callbackType` 必须为 `STREAM`；投放目标沿用现有 `CardTarget.robot(sender_staff_id)`。
3. **注册卡片回调**：`ekbs/stream.py` 目前只注册了 `ChatbotMessage.TOPIC`，需追加
   `/v1.0/card/instances/callback`（`Card_Callback_Router_Topic`）。
4. **回调处理**：
   - 解析 `CardCallbackMessage` 的 `outTrackId` / `userId` / `content`；
   - `userId` 映射到现有 `sender_staff_id` / `ekbs_user`，复用 `StreamMessageHandler` 的权限、限流、审计链路；
   - 按钮值 → 问题文本 → 走 `_ask_api`；「查看可查文档」→ 走 `mode=docs`；
   - 按官方要求回填 `messageId` ACK。
5. **降级**：没有模板 ID / 卡片创建失败时，自动回退到 P0 文本帮助（现有 `_reply_with_card` 已有失败回退骨架）。

## 验收标准

- 单聊点按钮能直接得到对应问题的回答，引用/权限/审计与手打问题一致；
- 群聊仍然零回复；
- 没有卡片模板时，用户仍能收到 P0 文本帮助，不报错；
- 卡片按钮文案与 `config/discovery_questions.json` 同源，避免两处漂移；
- 记录卡片发送/点击指标（可观测性）。

## 阻塞/前置条件

- 钉钉开发者后台：创建卡片模板权限、机器人卡片回调订阅权限；
- `ai_template_id`（以及需要的卡片模板变量名）；
- 真机联调：单聊卡片投放、按钮回传、`messageId` ACK。

## 风险

- 卡片接口有每月调用量配额（标准版累计 1 万次/月），需确认租户版本；
- 卡片回调的 `userId` 与聊天 `senderStaffId` 映射需要真机验证；
- 卡片按钮文案需随帮助示例一起维护，避免重新变成「主要讲了什么」式弱问法；
- 群聊已全局禁用，不要为卡片打开群聊回复。

## 决策

- **不半上线**：没有模板/回调权限前，保持 P0 文本方案；权限到位后再做 P1，不提前改消息通道。
