## 0. 先更正一处：第一步不是「数据采集」

你说的方向对（采集确实是业务流程的第一环），但**严格的第一步是「准入与前置检查」**。
原因是入库工具会在**动手之前**做闸门校验，配置不对时**整批快速失败** —— 若跳过前置，
你会看到"每个文件都失败"，而真正原因（闸门/密钥/分片）被埋在 N 条失败里。

代码依据（`ekbs/tools/import.py`）：

| # | 闸门 | 说明 |
|---|---|---|
| 1 | `assert_compliance_gate(real_corpus=not synthetic)` | **真实语料**必须先把 `permission.corpus_egress_ack` 置 `true`（可填 `corpus_egress_ack_ticket` 记确认编号）。合成/公开样本用 `--synthetic` 绕过，真实语料**不要**加 |
| 2 | `assert_l3_ingest_allowed(level)` | 入库 L3/L4 还要求 `l3_ingest_enabled` |
| 3 | 云端嵌入需要密钥 | `DASHSCOPE_API_KEY`（走云端配置时） |
| 4 | 目标分片必须存在或可派生 | `--shard-id` 显式给，或 `--dept-code` + `--level` 派生 |
| 5 | **扩展名白名单已单一来源** | 默认白名单 = `parser.SUFFIX_ENGINES`（63 种，含 `.pdf`），**不再需要 `--ext .pdf`**。`--ext` 是**替换**而非追加，给了就只导这些后缀 |

> 白名单与「配置允许但解析器没实现」是两件事：上传接口取
> `配置白名单 ∩ 解析器已实现` 的交集，`.ppt` / `.html` 这类只在配置里出现的格式会
> 返回 422 并说明原因，不会被静默丢弃。详见 `tests/test_ingest_extensions.py`。

**所以顺序是：第 0 步前置 → 第 1 步数据采集 → 第 2 步解析 → 第 3 步分块与索引 → 第 4 步检索 → 第 5 步问答 → 第 6 步权限红线 → 第 7 步运维。**

## 第 1 步：数据采集（入库）

### 1.1 文件放哪里

**放 `var/raw/<批次>/`**（按知识库/批次分子目录，便于小批试跑与回滚）：

```bash
mkdir -p var/raw/2026-09-27-首批/hr
cp <你的制度文件> var/raw/2026-09-27-首批/hr/
ls -la var/raw/2026-09-27-首批/hr/
```

* 为什么是这里：配置里 `data_dir: var`，`var/raw/` 就是「上传的原文件」目录（生产对应 `/data/ekbs/raw`）；
  且 `var/` 已被 `.gitignore` 忽略。
* ⚠️ **不要**放仓库根、`docs/`、`tests/` 等受版本控制的目录 —— 会被 `git add -A` 收进仓库，
  公司文档可能被推到远端。
* 命名建议：文件名能体现文档标题。解析器**可能整块丢弃文档标题行**，文件名是兜底标题来源。

**支持格式**：`.md .markdown .txt .docx .xlsx .pptx`（完整清单见 §2.0）；
**PDF/图片**：`.pdf` 已在默认白名单里（不用写 `--ext`），只需 MinerU 就绪；首次运行会下 2–3 GB 模型。

### 1.1b 从管理界面导入（**不用命令行**）

文件同样放进 `var/raw`，然后打开 `http://127.0.0.1:8000/admin` → 左栏「导入」。两种方式：

| 页签 | 适合 | 走哪条路 | 宽度 |
|---|---|---|---|
| **服务器目录导入** | 批量（几百份）、代码仓库、中文多级子目录 | 扫描 → 登记 `pending` → **worker 解析** | **63 种**（与 CLI 同一白名单） |
| **上传文件** | 临时插几份 | `/docs/upload` 三段式（分片 + 秒传） | **11 种**（配置白名单 ∩ 解析器） |

目录导入的完整动作：**逐层进入目录**（面包屑显示 `raw/人事制度/考勤`）→ **扫描预览**
（列出「将导入 / 跳过（已存在）/ 超限」，并给出闸门未开的原因）→ 填知识库/密级/可见部门 →
**执行导入** → 页面下方「解析队列」立刻显示 `待解析 N`。

**验证闭环（4 步）**：

```bash
TOKEN=$(curl -s -X POST localhost:8000/api/v1/auth/dev-token -H 'Content-Type: application/json' \
  -d '{"user_id":1}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["token"])')

# 1) 扫描（不写库）
curl -s -X POST -H "Authorization: Bearer ${TOKEN}" -H 'Content-Type: application/json' \
  -d '{"path":"","level":1}' localhost:8000/api/v1/import/scan | python3 -m json.tool | head -20

# 2) 执行（登记待解析）
curl -s -X POST -H "Authorization: Bearer ${TOKEN}" -H 'Content-Type: application/json' \
  -d '{"path":"","kb_id":1,"level":1,"dept_ids":["102"]}' localhost:8000/api/v1/import/run

# 3) 看队列（pending 应被 worker 迅速吃掉）
curl -s -H "Authorization: Bearer ${TOKEN}" localhost:8000/api/v1/import/queue

# 4) worker 没跑的话，队列会一直停在 pending —— 先确认服务：
bash scripts/dev_services.sh status
```

**预期与红线**：

* 导入**只登记不解析** —— 网页请求不会挂几十分钟；进度去「解析任务」页看。
* 路径**只能在 `data_dir/raw` 之内**：`..`、绝对路径、指向外部的软链接都会被拒（403）。
  这是刻意的 —— 否则等于把「读服务器任意文件」开放给任何有 `doc:document:create` 的账号。
* 合规闸未开时，扫描会把原因列出来、执行返回 **409**（不是 500，也不是"导了但没生效"）。
* 重复文件按**内容 checksum** 跳过（全局去重），不是按文件名。
* 一次最多登记 2000 份；超了**明确报错**，不会静默只导一部分。

### 1.5 一致性校验（**这步最关键**）

```bash
DB=var-cloud/index/ekbs.db     # 云端路径；离线路径是 var/index/ekbs.db
sqlite3 -header -column $DB "SELECT
  (SELECT COUNT(*) FROM ekbs_document WHERE status='published')                  AS 已发布文档,
  (SELECT COUNT(*) FROM ekbs_chunk)                                              AS 分块总数,
  (SELECT COUNT(*) FROM ekbs_chunk c WHERE c.chunk_type IN ('parent','child','table','figure')
     AND NOT EXISTS (SELECT 1 FROM ekbs_chunk k WHERE k.parent_id=c.chunk_id))   AS 可检索块,
  (SELECT COUNT(*) FROM ekbs_chunk WHERE faiss_row IS NOT NULL)                   AS 已入向量,
  (SELECT COUNT(*) FROM ekbs_chunk_fts)                                           AS FTS行数,
  (SELECT COALESCE(SUM(vector_count),0) FROM ekbs_shard WHERE status='active')    AS 分片登记向量;"
```

**预期（等式必须成立）**：

```
可检索块 == 已入向量 == FTS行数 == 分片登记向量
分块总数 == 父容器 + 可检索块      （父容器**不进**向量库，这是设计）
```

> ⚠️ **判据是「叶子块」而不是 `chunk_type='child'`** —— 这是 2026-09 修掉的一处跨层
> 不一致，写在这里免得重犯：
>
> | 来源 | 检索单元是什么 | 为什么 |
> |---|---|---|
> | Markdown | `child` | `parent` 是上下文容器（有子块），向量化会与子块重复 |
> | **代码** | **`parent`（符号块本身）** | 顶层 `class`/`def` **没有子块**，写死 `child` 就会让整个代码库「存了但搜不到」 |
> | 图片 | `figure` | 图上文字（OCR/题注）要能检索，需求「图片有实际意义」才成立 |
> | 超长符号 | 它的 `child` 分片 | 此时父块才退化成纯容器 |
>
> 口径唯一实现在 `ekbs/ingest/retrievable.py`；`tests/test_ingest_code_and_figures.py`
> 里有 `test_no_module_redefines_what_is_retrievable` 防止它再散落回各模块。

> ⚠️ **别把「分块总数 ≠ 向量数」当故障**：父容器只用于**父块扩展**回上下文，
> 既不向量化也不进 FTS。实测演示库：分块 16（父 8 + 子 8），向量 8，FTS 8 —— 完全正常。
> 我第一版方案把等式写成「向量 = 分块总数」，那样测会误判成坏了（16 ≠ 8）。

> 🔧 **手工改库后必须用项目 API 动 FTS**：`ekbs_chunk_fts.chunk_id` 是 FTS5 的
> `UNINDEXED` 列且**以字符串存入**（`FtsIndex.upsert_chunks` 里 `str(chunk_id)`）。
> 裸 SQL `DELETE FROM ekbs_chunk_fts WHERE chunk_id IN (50)` 用整数比较**一行都删不掉**
> （FTS5 列无 affinity，不会把字面量转成文本），会留下悬挂行。请用
> `FtsIndex.delete_chunk_ids()` / `upsert_chunks()`。

**不过**：差值指向不同故障 —— FTS 少 = 分词/写入问题；FAISS 少 = 向量化失败；分片登记多 = 索引重建没跟上；父容器数对不上 = 分块器切分异常。

## 第 2 步：解析

### 2.0 支持的文件类型（**两张清单，别混为一谈**）

权威来源只有一处：`ekbs/ingest/parser.py::SUFFIX_ENGINES`（**63 种**）。
但「谁按哪张清单收文件」有两条路，宽度不同 —— 复核时最容易在这里张冠李戴：

| 入口 | 生效清单 | 宽度 |
|---|---|---|
| **批量导入 CLI**（`ekbs.tools.import`） | `SUFFIX_ENGINES` 全量 | **63 种** |
| **上传接口 HTTP**（`/api/v1/docs/upload/init`） | 配置 `limits.file_ext_whitelist` ∩ `SUFFIX_ENGINES` | **11 种** |

按引擎分组的 63 种：

| 引擎 | 数量 | 后缀 |
|---|---|---|
| `mineru` | 4 | `.pdf` `.png` `.jpg` `.jpeg` |
| `docx` | 1 | `.docx` |
| `doc` | 1 | `.doc`（macOS `textutil`） |
| `xlsx` | 1 | `.xlsx` |
| `xls` | 1 | `.xls`（`xlrd`，只读旧版） |
| `pptx` | 1 | `.pptx` |
| `text` | 54 | `.md` `.markdown` `.txt` + **51 种代码后缀** |

51 种代码后缀：`.bash .bat .c .cc .cjs .clj .cpp .cs .cts .cxx .dart .erl .ex .exs .fish .go
.groovy .h .hh .hpp .hs .java .jl .js .jsx .kt .kts .lua .m .mjs .mm .mts .php .pl .proto .ps1
.py .pyi .pyw .r .rb .rs .scala .sh .sql .svelte .swift .ts .tsx .vue .zsh`

**上传接口能收的 11 种**：`pdf docx doc pptx xlsx xls txt md png jpg jpeg`

> ⚠️ **代码文件目前只能走 CLI 批量导入**：从上传接口传 `.py` 等会被 **422**
> （配置白名单里没有代码后缀）。这不是 bug，但若要在管理台上传代码，改的是**配置**
> （往 `file_ext_whitelist` 加后缀即可，取交集那步会自动放行），不需要动解析器。
> 已用 `tests/test_ingest_extensions.py::test_upload_api_is_config_intersection_and_is_narrower_than_cli` 钉住。

> ⚠️ **明确不支持**：`.csv` `.json` `.rst` `.ini` `.toml`（不在 63 种之内，
> CLI 按"跳过"计数、不报错）；`.ppt` `.html`（**配置里有、解析器没实现** →
> 上传时 422 并说明原因，不会静默收下再变乱码）。

| 子项 | 操作 | 预期 |
|---|---|---|
| 文本类 | 上一步已覆盖 | `.md/.markdown/.txt` 及 **51 种代码后缀**直接出 markdown。⚠️ `.csv/.json/.rst/.ini/.toml` **当前不支持**（不在 `SUFFIX_ENGINES` 里，导入时按"跳过"处理） |
| **PDF / 图片** | MinerU 环境变量 | 走 `mineru -p … -o …` 子进程；产物 `_content_list.json` → 页码映射 |
| **旧版 Office** | 直接导入即可 | `.doc` → `textutil` 转 docx（**macOS 自带，无需 LibreOffice**）；`.pptx` → `python-pptx`（逐页 Slide）；`.xls` → `xlrd`（**只读旧版**，`.xlsx` 另走 openpyxl） |
| **代码文件** | 直接导入即可 | 51 种后缀由 `parser.SUFFIX_ENGINES` 认成文本引擎，pipeline 再按后缀路由到符号切分（见第 3 步） |
| **图片不丢** | 见下方 §2.1 | 文档内图片落盘 + `figure` 块进向量与 FTS，可检索、可回源 |
| 页码落库 | 查 `ekbs_chunk.page_from/page_to` | MinerU 解析件应有页码（文本类为 NULL，属正常，不伪造） |
| 失败可追溯 | `curl /api/v1/parse/tasks` 里 `status=failed` | 原因只在日志（Schema 无 error 列，已知项） |

**不过**：PDF 一个都没导入 → 确认 `EKBS_MINERU_BIN` 指向存在的可执行文件（白名单已含 `.pdf`，不用再写 `--ext`）。

### 2.1 图片必须「不丢 + 可检索」（四要件）

只把图片存下来不算过关，这四件事缺一件就是「存了但搜不到」：

| # | 要件 | 检查方式 | 期望 |
|---|---|---|---|
| 1 | **落盘持久** | 解析目录里真有文件 | `var/parse/<sha\|doc_id>/images/<sha>.jpg`；不能是 `tempfile` 临时目录（会被回收，早期就是踩了这个坑） |
| 2 | **成块可检索** | `SELECT chunk_type, image_path, faiss_row FROM ekbs_chunk WHERE chunk_type='figure'` | `faiss_row` 非空（进了向量）、FTS 里有对应行（可被关键词命中） |
| 3 | **可回源** | `curl -H "Authorization: Bearer $TOKEN" .../assets/figure/<chunk_id>` | 200 且 `Content-Type: image/jpeg`；无权用户 403 |
| 4 | **无信息图不落块** | 既无题注又无 OCR 的图 | 直接跳过（`figure_skipped_no_text`），不产生垃圾块 |

图片检索文本 = **题注 + OCR**：`EKBS_FIGURE_OCR`（默认开）、`EKBS_FIGURE_OCR_MAX`（默认 12 张/篇）、
`EKBS_FIGURE_OCR_MIN_KB`（默认 8，太小的图不做 OCR）。关掉 OCR 的话，纯图形（无题注）的图就检索不到。

```bash
# 一条命令看图片三要件
sqlite3 -header -column var/index/ekbs.db "
SELECT c.chunk_id, c.figure_id, c.page_from, c.image_path,
       (c.faiss_row IS NOT NULL) AS 已入向量,
       EXISTS(SELECT 1 FROM ekbs_chunk_fts f WHERE f.chunk_id = CAST(c.chunk_id AS TEXT)) AS 已入FTS
FROM ekbs_chunk c WHERE c.chunk_type='figure' LIMIT 20;"
```
> 注意 `f.chunk_id` 要 `CAST(... AS TEXT)`：FTS 里存的是字符串（见 §1.5 的提醒）。

## 第 3 步：分块与索引

不同来源走**不同分块器**，但「谁是检索单元」的口径唯一（`ekbs/ingest/retrievable.py`）：

| 来源 | 分块器 | 分块形态 | 检索单元 |
|---|---|---|---|
| 普通文档 | `chunk_markdown` | 小节 → 父容器 + 子块 | `child` |
| **代码** | `chunk_code` | 顶层符号各一块；超长符号 → 父容器 + `#n` 子块 | 符号块（短符号是 `parent`，超长时是它的 `child`） |
| 文档内图片 | `chunk_markdown(figures=…)` | 一图一块 | `figure` |

代码块的 `heading_path` 就是**可读的符号路径**，这是代码库检索效果的关键：

```
ekbs/ingest/pipeline.py > IngestPipeline            ← 超长类：容器，faiss_row=None
ekbs/ingest/pipeline.py > IngestPipeline#1 … #10    ← 子块，入向量
ekbs/ingest/pipeline.py > IngestResult.as_dict      ← 短符号：自身入向量
ekbs/ingest/pipeline.py > <module>                  ← 模块级零散语句聚成一块
```

```bash
# 分块树（父块/子块结构）
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8000/api/v1/chunks/documents/2/tree | python3 -m json.tool | head -40
# 分片登记 vs 实际文件
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/v1/system/shards | python3 -m json.tool
```
**预期**：`ekbs_shard.vector_count` 与 FAISS 实际 `ntotal` 一致；`dim` 与嵌入维度一致。
**红线**：换嵌入模型后旧分片会让进程**拒绝启动**（指纹闸），这是设计行为，处理方式是重建分片而非无视。

> ⚠️ **重建 / 换级 / 巡检与入库必须同口径**：`rebuild_shard`、权限变更的换级重嵌、
> 三方对账、发布闸门、导入统计都引用同一份 `RETRIEVABLE_PREDICATE`。
> 早先它们各自写死 `chunk_type='child'`，导致重建一次就悄悄丢掉代码与图片的向量。

## 附：失败定位速查

| 现象 | 先看哪里 |
|---|---|
| 入库**整批**失败 | 第 0 步五项：合规闸 / 密钥 / 分片 / 扩展名 |
| PDF 导入 0 个文件 | `EKBS_MINERU_BIN` 是否指向存在的可执行文件（`.pdf` 已在默认白名单，`--ext` 反而是**替换**语义，写了就会把别的后缀排除掉） |
| 代码/图片**落了库但搜不到** | 查 `faiss_row` 是否为空：若为空，多半是又有模块把「可检索」写死成 `chunk_type='child'`（见 §1.5 与 `ekbs/ingest/retrievable.py`） |
| 重建分片后**向量变少** | 同上：重建必须与入库同口径（`rebuild_shard` 已引用 `RETRIEVABLE_PREDICATE`） |
| 手工删库后 FTS 仍有行 | `ekbs_chunk_fts.chunk_id` 是**字符串**，裸 SQL 用整数删不掉；用 `FtsIndex.delete_chunk_ids()` |
| 403 缺权限点 | `/auth/me` 的 `permissions[]`；接口要求的权限码 |
| 429 | `limits.per_user_qps / global_qps` |
| 该有答案却拒答 | `min_score`、该分片是否可见、`top_score` 实际值 |
| 刚入库搜不到 | worker/索引是否在跑；分片索引外部重载 |
| 管理台导入后一直「待解析」 | worker 服务没跑（`bash scripts/dev_services.sh start worker`）；导入只登记不解析 |
| 管理台侧栏点了没反应 / 找不到导入入口 | 页面靠原生 hash 路由（`#/导入`）。侧栏顶部有常驻的「**＋ 导入文件**」按钮；导入页默认就是「上传文件」页签。若无按钮，按 `Cmd+Shift+R` 强刷一次 |
| 导入报 409 | 合规闸/L3 闸未开，响应里的 detail 就是原因（界面会显示在扫描结果里） |
| 导入报 403 | 路径超出 `data_dir/raw`（`..` / 绝对路径 / 指向外部的软链接） |
| 换模型后起不来 | 嵌入指纹闸（设计行为）→ 重建分片 |
| 端口占用 | 8000/8100 被别的服务占着（验收脚本会明确报出） |
