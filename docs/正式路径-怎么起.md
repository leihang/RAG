# 正式路径（真实云端模型）怎么起

> 用途：**部署前的功能测试**。mock 配置适合验流程，但验不出真实模型的报文差异、
> 限流、超时、分数分布 —— 找 bug 必须在正式路径上走。

## 一、两个配置的唯一区别是 provider

| | `config/application.dev.yaml` | `config/application.cloud.yaml` |
|---|---|---|
| embed | `mock` | `dashscope / qwen3.7-text-embedding-flash@1024` |
| rerank | `mock` | `dashscope / qwen3.7-text-rerank`（`min_score=0.60`） |
| llm | `mock` | `dashscope / qwen-max` |
| 数据目录 | `var/` | `var/`（**必须一致**，见下） |
| 合规闸 | — | `corpus_egress_ack: true` |

> ⚠️ 早先 cloud 配置把 `database.path` 指到 `var-cloud/index/`，于是 DB 与 raw/parse/分片
> **分居两棵树**，清一次 `var-cloud` 就起不来（报「数据库文件不存在」，看不出是配置分叉）。
> 已对齐：两个配置的 `data_dir` / `log_dir` / `database.path` 完全相同。

## 二、密钥

```bash
ls -l ~/.ekbs/secrets.env      # 必须存在且权限恰为 600
```

`scripts/dev_services.sh` 现在会像生产 launchd 那样 `set -a; source ~/.ekbs/secrets.env; set +a`，
所以**不需要**手工 export（早先忘了 source，导致"生产能起、dev 起不来"）。

## 三、起服务

```bash
cd /Users/lh/Documents/工作学习/AI项目/RAG
export EKBS_CONFIG=config/application.cloud.yaml
bash scripts/dev_services.sh stop all
bash scripts/dev_services.sh start all      # api / worker / scheduler
curl -s localhost:8000/health/deps | python3 -m json.tool   # embed/llm/rerank 三个都要 true
```

**必须三个服务一起重启**：它们各自 import 一份代码与配置。改了
`ekbs/index/`、`ekbs/ingest/`、`ekbs/retrieval/` 下任何文件后尤其如此 —— 否则会出现
「api 是新代码、worker 是旧代码」，表现为用户上传直接失败（本仓库踩过两次）。

## 四、换模型后必须重建分片（指纹闸）

嵌入模型变了 → 分片里登记的是旧指纹 → **进程拒绝加载**（这是设计的安全网，不是故障）。

```bash
set -a; . ~/.ekbs/secrets.env; set +a
export EKBS_CONFIG=config/application.cloud.yaml
.venv/bin/python -m ekbs.tools.rebuild_shard --shard-id kb_all_L1 --all
```

真实模型下这一步会**真的调用云端 API**（对每个可检索块嵌入一次），有 token 成本。

## 五、合规闸（真实语料）

`方案 00 §7` 的硬闸门：`corpus_egress_ack=true` 才允许真实语料入库（入库即全量出网）。
**它是给"人"看的控制**，不是代码限制 —— 改它等于签一份"我确认公司文档可以出网"。

```yaml
permission:
  corpus_egress_ack: true
  corpus_egress_ack_ticket: "2026-09-29 用户确认：正式路径功能测试，语料可出网"
```

合成/公开样本可以绕过：导入时加 `--synthetic`（**真实语料不要加**，那是谎报来源）。

## 六、切回 mock（验流程、不花钱）

```bash
export EKBS_CONFIG=config/application.dev.yaml
bash scripts/dev_services.sh stop all && bash scripts/dev_services.sh start all
```

切回后分片指纹又不匹配 → 同样要重建（或者直接清空重来）。
