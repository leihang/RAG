# 删除文档：到底删掉了什么

> 操作步骤（怎么点、怎么清）在 `文件放在哪-怎么清.md`；这份只讲**删除的语义与证据**，
> 避免两处各写一份流程然后漂移。

## 1. 删除一次，清掉这些

`DELETE /api/v1/docs/documents/{doc_id}`，或界面「删除 / 批量删除」
（两者共用同一个实现 `ekbs/api/docs.py::_perform_delete`）。

| # | 位置 | 说明 |
|---|---|---|
| 1 | `ekbs_chunk_fts` | 该文档所有分块的全文索引行（先删，避免悬挂） |
| 2 | `ekbs_chunk` | 该文档全部分块（父/子/表格/图片块） |
| 3 | `ekbs_document` | 文档记录本身（**硬删除，没有回收站**） |
| 4 | `ekbs_perm_change_log` | 写一条删除留痕（可追溯，**刻意保留**） |
| 5 | `policy_version` | +1 → 让所有缓存键与权限指纹失效（原则 P1，下次请求立即生效） |
| 6 | **FAISS 分片里的向量** | `IndexIDMap2.remove_ids` **真删**（标签就是 `chunk_id`），原子落盘 + 回写 `vector_count` |
| 7 | **磁盘原件** `<data_dir>/raw/<kb_code>/…` | `unlink`（默认删；接口带 `purge_assets=false` 可保留） |
| 8 | **解析产物** `<data_dir>/parse/<doc_id>/` | 整目录删掉 |

第 7、8 条是后来补的：原先删除只清库与向量，磁盘上的原件与解析产物要人工跑
`ekbs.tools.gc --delete` 收尾。用户实测反馈「删了之后原文档还在」—— 从"删除"这个动作的
语义看，那确实没删干净，所以现在默认一并清掉。

> ⚠️ 越界保护：只有 `source_path` 确认落在 `data_dir/raw` **之内**才 unlink，
> 否则只告警、不动文件（否则一行被篡改的 `source_path` 就能把删除接口变成任意文件删除）。

实测（2026-09-29，走管理台那条批量接口）：

```
删除前  var/raw/internal_public_document/删除自检.md 存在
POST /docs/documents/batch {"action":"delete", ...}
→ {"succeeded":1,"results":[{"doc_id":3,"ok":true,"status":"deleted","deleted_chunks":2,
   "assets_removed":["…/var/raw/internal_public_document/删除自检.md"], …}]}
删除后  该文件已不存在；doc=0 chunk=0；分片 ntotal=0
```

## 2. 删完仍然"剩下"的东西（都不是 bug）

| 剩下什么 | 为什么 | 要不要处理 |
|---|---|---|
| `var/index/<分片>.faiss`（90 字节，`ntotal=0`） | 分片是**注册在库里的基础设施对象**（`ekbs_shard` 行、分片级 ACL 都指向它），不随某一份文档消失。文档删光后它是空壳，下次有同部门/同密级的文档进来直接复用 | 不用。看到文件还在 ≠ 向量还在，用 `faiss.read_index(p).ntotal` 看才是真相 |
| `ekbs_cache` 里旧的答案/检索缓存 | 行还在，但键含 `policy_version`，版本已 +1 → 逻辑上不可达 | 不用，TTL 与调度器作业会收 |
| 进程内 LRU | 同上，按指纹分区 | 不用 |
| `var/tmp/<upload_id>/` | 只在上传中断/失败时残留（成功上传会自己删） | `ekbs.tools.gc --delete` |

**刻意不动**：`ekbs_qa_citation` / `ekbs_doc_access_log` 里的历史引用 —— 审计要求它们保留
（"谁在什么时候引用/访问过什么"，删除文档不该抹掉这段历史）。

## 3. 与方案的差异（诚实交代）

方案 P5 要求「删除类操作一律**软删除 + 回收站 30 天**；发布/下线保留版本快照」。
当前实现是**硬删除**：删了就是删了，只能靠重新导入原件恢复。

这也是为什么现在把磁盘原件一起删掉、而不是"留着当唯一的后悔药"：产品里没有恢复入口，
留着只是一份看不见的垃圾（一份 22 MB 的 PPT 就这么躺了很久）。
要按方案补回收站，需要 `ekbs_document.deleted_at` + 列表过滤 + 恢复接口 + 30 天清理作业；
届时"删除"应改为软删除，`purge_assets` 变成回收站到期后的物理清理动作。
