- **语料**：当前知识库 `internal_public_document` 的 **695 个可检索块**（16 篇文档，已含最新清洗/分片修复）；文本口径 = 生产同款 `retrieval_text()`（标题路径 + 正文）。
- **查询**：金标题集 **45 条正例**（原题集 28 + 同义改写 17）；相关块由金标的`must_contain` 片段 / `must_hit_doc` 定位（45/45 全部解析成功）。
- **脚本**：`~/Desktop/python_混合检索评测/hybrid_rag_eval.py`，**文件未做任何修改**（通过 `importlib` 原样加载；BM25、MinMax 归一化、alpha 融合、Recall@K 都是它自己的代码）。

## 三个结论

1. **脚本的 BM25 在中文上是空转**：它用 `doc.split()` 分词：**查询被切成 1 个 token**（`电梯一年要花多少保养费`），而语料块被切成 ~17 个空白分隔的长片段 → 两边**没有任何共享 token**，实测 710 个块的 BM25 分数**全为 0.0000**；MinMax 对全等数组返回全 0，于是融合退化成**纯向量检索** —— 所以 Run A 在 alpha 0.1~0.9 之间 **Recall@5 完全相同（0.1184）**。脚本自己的注释也写了「生产环境建议接入 jieba」。
2. **换成 jieba（Run B）后，BM25 权重越大反而越差**：Recall@5 从 0.1199（alpha=0.1）单调掉到 0.0810（alpha=0.9），Hit@5 从 95.6% 掉到 86.7%（alpha=0.5 时）。根因是脚本的**逐查询 MinMax 归一化**：它把很弱的 BM25 信号硬拉到 [0,1] 全域，噪声项因此在融合中与向量侧等权 —— 这正是我们生产用**原始分数**做 alpha 融合（`fusion=alpha, hybrid_alpha=0.85`）而不做 MinMax 的原因。
3. **单级稠密检索的召回已经很强，生产的 rerank 买的是「排序」**：原题集上脚本纯向量 Hit@5 = 100.0%，甚至**高于**生产管线的 96.4%（生产有 1 例被阈值拒答，见下），但 Hit@1 只有 57.1%、MRR 0.742；生产 MRR 0.896（原题集）—— 差距全在**排序**上：云端 rerank 把命中块从第 2~5 位抬到第 1 位。换句话说，**召回靠稠密检索，精度靠 rerank**。

## 生产阈值拒答的代价（原题集）

生产管线原题集 Hit@5 = 96.4%（1 例被拒答），而纯稠密检索（脚本 Run A）在同题集 Hit@5 = 100.0%。逐条核对被拒的那几题：

| 用例 | 生产拒答原因 | 脚本 Run A 能捞到吗（best_rank） |
|---|---|---|
| course-rag-multimodal | below_threshold | 是，第 1 位 |

> 这正是生产与「教程脚本」的取舍差异：生产用 `min_score` 宁可拒答也不给低置信答案（负例不误放），代价是**偶发把能答的题也拒了**；脚本没有阈值，永远返回 Top-K。

**逐条核对结果：这一例是金标题集的假目标，不是检索缺陷。** 库里唯一匹配该片段的块是：

```text
chunk_id=4264  doc_id=41  chunk_type=parent  内容仅 7 字：「4.RAG调优」
heading_path=「3.RAG多模态数据处理」   ← 只有标题、没有正文的幻灯片页
```

即：`retrieval_text` = 「3.RAG多模态数据处理
4.RAG调优」共 12 字，**这个块里没有任何可作答的内容**。生产把它 rerank 到低于 `min_score=0.65` → 拒答（**判别正确**：没有答案就不该编）；脚本判它「命中」，是因为金标的判据是**片段字符串匹配**（匹配到了 heading_path），并不判断「这个块能不能回答问题」。

→ **处置建议**：① 该金标用例应退役或改判据（它测的是「标题路径被检索到」，不是「答得出来」）；② 或按发现 81 的待办，让只有标题的页也生成**标题块**（正文即标题），这样它才是有内容的检索单元。两者选一即可，不要靠调低阈值掩盖。

## 两个必须说明的口径差异（否则数字会被误读）

* **Recall@K 的分母**：脚本按**块**算（`|命中块| / |相关块|`），而金标里同一片段常命中多个块（相关集大小 min=1、中位=2、max=201；>5 的占 15/45）→ Top-5 最多只能覆盖 5/|相关集|，所以 0.1184 这个绝对数**不代表检索质量**，只在 Run A/Run B 之间、以及 alpha 之间做比较才有意义。
* **脚本的融合分没有绝对含义**：alpha=0.5 时 8 条负例的 top-1 分数**全部恰好是 0.5000**（MinMax 后 top-1 恒为 1.0，再乘 0.5 权重）→ 无法据此设相关性阈值；生产的 `min_score=0.65` 之所以能用，是因为它作用在**云端 rerank 的原始分**上。
