## 9. 上传「文件夹」的当前口径（2026-09-28 定）

方案 §1.5 把「目录树管理」列为首期**不做**（首期用扁平目录 + 标签），所以系统里
**没有可授权的目录对象**。但用户传文件夹时不该"看起来什么都没保留"，当前实现是：

| 维度 | 现状 |
|---|---|
| 浏览器侧 | 「选择文件」+「选择文件夹」（`webkitdirectory`）+ 拖拽文件夹递归展开 |
| 落盘 | 按**相对路径**保留层级：`<data>/raw/<sha>/制度/2026/预算表.xlsx` |
| 文档标题 | 取相对路径（去扩展名）：`制度/2026/预算表2026` —— 于是"制度/2026"这段可被搜索与筛选 |
| 权限 | 仍然只有 **KB / 密级 / 部门** 三个维度；**没有目录级 ACL**（方案未设计） |
| 秒传 | 按**内容**去重：同一份内容再次上传会命中秒传并复用已有文档，**不会**因为放在别的目录而产生第二条 |

若要真正的"目录"（可建、可移动、可单独授权），那是 schema + API + UI 三层的改动，
且方案把它排在二期 —— 需要你确认后再做。
